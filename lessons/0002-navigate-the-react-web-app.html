Why this matters for your mission

Your mission now has a React half: change and extend the web app with the same confidence as the API. Every change starts with one question: where does this live? In this app the answer is never "somewhere in a component". It is always one of three folders.

You already know React from Namaste React. Keep components, props, JSX and routes. Three habits from the course change here. The table shows them.

In the course you…Here you…Folder
called fetch inside useEffectcall a function from api/ through useQuery (reads) or useMutation (writes)web/src/api/
kept helpers in utils/ and filtered lists into a second useStatewrite a pure function and call it during renderweb/src/domain/
read localStorage in a componentread a store in api/ with useSyncExternalStoreweb/src/api/

Why no useEffect? React's own guide says most effects are not needed: derive values during render, and do user work in event handlers (react.dev, You Might Not Need an Effect). ESLint refuses useEffect in web/src (web/eslint.config.js).

The map: three layers and one route table

web/src/
├── main.tsx        creates the router (createBrowserRouter) and the QueryClient
├── App.tsx         QueryClientProvider + RouterProvider
├── routes.tsx      every URL → screen; teacher-only screens sit under requireTeacher
├── domain/         PURE rules. No React, no fetch, no storage.     login-errors.ts
├── api/            The ONLY place for fetch and browser storage.   http-client.ts, accounts-api.ts,
│                                                                   account-token-store.ts, login-reason-store.ts
└── features/       React screens, grouped by area
    ├── accounts/       LoginPage.tsx, use-signed-in-account.ts
    ├── game-session/   GameSetupPage.tsx (placeholder)
    └── shared/         ErrorBanner.tsx, TeacherRoute.tsx, require-teacher.ts
web/tests/          screen tests: render the real app over a fake fetch

Imports go one way: features → api and features → domain. domain may not import api or React. api may not import features or React. npm run lint:boundaries enforces this.

Trace one click: “Sign in”

Open each file as you read its step. The colour shows the layer.

1 · Event handlerfeatures/accounts/LoginPage.tsx · handleSubmit

The form's onSubmit reads the email and password. It calls signInCredentialsProblem first. With an empty field, it stops here and sends nothing.

2 · Pure ruledomain/login-errors.ts · signInCredentialsProblem

Returns null or { sentence, focusField }. No React, no network: easy to reason about.

3 · MutationLoginPage.tsx · signIn = useMutation(…)

signIn.mutate(credentials) runs mutationFn. TanStack Query tracks isPending and error, so the buttons disable themselves (TanStack Query, Mutations).

4 · API functionapi/accounts-api.ts · signInInstructor

Trims the email and calls apiRequest("POST", "/api/v1/accounts/sign-in", …).

5 · The one HTTP clientapi/http-client.ts · apiRequest

Calls fetch. Logs [API] POST /api/v1/accounts/sign-in -> 200 in development. Turns any refusal into an ApiHttpError { status, code, message, details }.

6 · Token storeapi/account-token-store.ts · saveAccount

Writes the Account Token to localStorage and notifies its listeners. useSignedInAccount subscribes with useSyncExternalStore, so every screen that shows the teacher re-renders (react.dev, useSyncExternalStore).

7 · NavigateLoginPage.tsx · onSuccess → navigate("/setup")

The route /setup sits under the requireTeacher loader in routes.tsx. The loader runs before the screen renders (React Router, Data Loading). A token exists, so TeacherRoute renders and confirms it with useQuery → GET /api/v1/accounts/me.

On failure the path turns at step 5. apiRequest throws an ApiHttpError, and signIn.error holds it. During render, loginErrorView(error) in domain/ turns it into a sentence. ErrorBanner shows that sentence.

Practice 1: pick the folder

Answer from memory first. Scroll up only after you commit to an answer.

Practice 2: type the file

Harder: no options. Type the path from memory, for example web/src/api/http-client.ts.

Practice 3: find it in the running app

  1. Start the app (see web/README.md, Quick start): npm run dev:prototype, then npm run dev:web.
  2. Open http://localhost:5173/login and the browser console.
  3. Sign in with a wrong password. Find the [API] … -> 401 line.
  4. Without searching, name the file that printed it and the file that chose the sentence on screen. Then check with grep -rn "\[API\]" web/src.
  5. Delete cc-account-token-v1 in DevTools → Application → Local Storage while on /setup. Before you reload, write down where you will land and which sentence you will read. Then reload and check. (Bonus: why did nothing change before the reload? Hint: which tabs receive the storage event?)
