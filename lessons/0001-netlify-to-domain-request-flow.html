How a Request Flows Step-by-Step Across Our 7 Hexagonal Classes

Tracing GET /api/v1/packs/diabe-teach from netlify/functions/api.ts through AppRuntime, OpenApiHttpApp, GetPackByIdHttpHandler (BaseHttpHandler), GetCurriculumPackByIdUseCase, MongoCurriculumPackRepository, and CurriculumPackProjector.

The Big Picture: One Entrypoint, 100% Cohesive Classes, Zero Loose Functions

Every implementation file in src/ is now a cohesive class, and every TypeScript interface/contract lives in its own dedicated *.types.ts, *.port.ts, or *.dto.ts file. Runtime configuration lives right at the top of src/ in src/app-runtime.ts (AppRuntime) so nothing is hidden inside a subfolder, and all MongoDB connection/collection logic is encapsulated inside src/adapters/outbound/.

Step-by-Step Class Walkthrough

Step 1 · Top-Level AppRuntime Class netlify/functions/api.ts → src/app-runtime.ts (class AppRuntime)

When a request hits /api/v1/* on Netlify Functions v2, Netlify invokes netlify/functions/api.ts. That file delegates to the visible top-level AppRuntime class in src/app-runtime.ts, which reads environment variables (AppRuntime.loadEnvConfig()), wires MongoCurriculumPackRepository.fromConfig(...) and HmacCapabilityTokenAdapter once per warm container (AppRuntime.getProductionDependencies()), and instantiates new OpenApiHttpApp(deps): 

// netlify/functions/api.ts
import type { Config } from "@netlify/functions";
import { AppRuntime } from "../../src/app-runtime.js";

export default AppRuntime.createServerlessHttpHandler();

export const config: Config = AppRuntime.defineServerlessRouteConfig({
  path: "/api/v1/*",
  method: ["GET", "POST", "PUT", "PATCH", "DELETE"],
});
Step 2 · OpenApiHttpApp Class & x-api-key Gate src/adapters/inbound/http/create-app.ts (class OpenApiHttpApp)

Inside OpenApiHttpApp (which implements HttpApp), OpenAPIBackend reads docs/api/openapi.yaml. When openApiHttpApp.fetch(request, context) runs:

  1. It matches the path template /api/v1/packs/{packId} and resolves operationId: getCurriculumPackById.
  2. It executes securityHandlers.ApiKeyAuth, which calls BaseHttpHandler.verifyApiKeyHeader(request.headers.get("x-api-key"), deps) using timing-safe comparison. If invalid, unauthorizedHandler returns 401 UNAUTHORIZED_TOKEN via BaseHttpHandler.jsonResponse.
  3. It extracts c.request.params.packId ("diabe-teach") and calls getPackByIdHandler.handle(request, context).
Step 3 · GetPackByIdHttpHandler extends BaseHttpHandler src/adapters/inbound/http/get-pack-by-id.handler.ts + endpoint-handler.factory.ts

Instead of loose procedural functions, every endpoint is a class extending the abstract BaseHttpHandler<TQuery, TResult> class. Calling getPackByIdHandler.handle(request, context) runs the template method: 

export class GetPackByIdHttpHandler extends BaseHttpHandler<
  GetCurriculumPackByIdQuery,
  GetCurriculumPackByIdResult
> {
  readonly #useCase: GetCurriculumPackByIdUseCase;

  public constructor(deps: GetPackByIdHandlerDependencies) {
    super(200);
    this.#useCase = new GetCurriculumPackByIdUseCase(deps);
  }

  public transformRequest({ request, context }: HttpRequestInput): GetCurriculumPackByIdQuery {
    return {
      packId: this.#resolvePackIdFromContext(context),
      bearerToken: BaseHttpHandler.parseBearerTokenHeader(request.headers.get("authorization")),
    };
  }

  protected async execute(query: GetCurriculumPackByIdQuery): Promise<GetCurriculumPackByIdResult> {
    return this.#useCase.execute(query);
  }
}
Step 4 · GetCurriculumPackByIdUseCase Class src/application/use-cases/get-curriculum-pack-by-id.use-case.ts

GetCurriculumPackByIdUseCase.execute(query) orchestrates the business rule using only Application Ports and Domain classes:

  1. If query.bearerToken is present, it verifies the token via CapabilityTokenPort.verifyToken to determine whether callerRole is "instructor" or "participant".
  2. It validates the slug via PackId.create(query.packId).
  3. It queries this.#packRepo.findById(packId) on CurriculumPackRepositoryPort.
Step 5 · MongoCurriculumPackRepository, MongoConnectionManager & CurriculumPack Classes src/adapters/outbound/mongo-curriculum-pack-repository.ts + mongo-client-singleton.ts

All MongoDB logic lives inside classes in src/adapters/outbound/:

  • Built-in fast path ("diabe-teach"): MongoCurriculumPackRepository.findById(packId) returns the frozen 49-card DIABE_TEACH_PACK (CurriculumPack class) in O(1) from memory with zero MongoDB queries.
  • Custom pack path (e.g., "cardio-teach"): MongoCurriculumPackRepository.fromConfig calls MongoConnectionManager.getDatabase(uri, dbName), queries the curriculum_packs collection, and rehydrates CurriculumPack.create(doc).
Step 6 · CurriculumPackProjector Class & BaseHttpHandler Response Mapping src/application/dtos/curriculum-pack-projector.ts → endpoint-handler.factory.ts

CurriculumPackProjector.toPublicDto(pack, { includeAnswerKeys: callerRole === "instructor" }) projects an immutable PublicCurriculumPackDto that strips correctIndex and explanation for anonymous/participant callers. Finally, BaseHttpHandler.handle() returns BaseHttpHandler.jsonResponse(result, 200)—or catches any DomainError and converts it via BaseHttpHandler.mapDomainErrorToResponse(error).
