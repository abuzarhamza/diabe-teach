The Big Picture: One Entrypoint, Four Clean Rings

In our architecture, there is only one serverless entrypoint (netlify/functions/api.ts) and only one routing table (docs/api/openapi.yaml, powered by the official openapi-backend framework). Every file strictly separates interfaces/contracts (*.types.ts, *.port.ts, *.dto.ts) from classes and functions (*.ts).

Step-by-Step Code Walkthrough

Step 1 · Netlify Entrypoint & src/config/ netlify/functions/api.ts → src/config/runtime.config.ts

When a request hits /api/v1/* on Netlify Functions v2, Netlify invokes the default export in netlify/functions/api.ts. That file delegates to createServerlessHttpHandler() in src/config/runtime.config.ts, which loads environment variables (MONGODB_URI, CAPABILITY_TOKEN_SECRET, API_KEY) once per warm container via getProductionDependencies() and calls app.fetch(request, context). 

// netlify/functions/api.ts
export default createServerlessHttpHandler();

export const config: Config = defineServerlessRouteConfig({
  path: "/api/v1/*",
  method: ["GET", "POST", "PUT", "PATCH", "DELETE"],
});
Step 2 · Central OpenAPI YAML Router & x-api-key Gate src/adapters/inbound/http/create-app.ts + docs/api/openapi.yaml

Inside createApp(deps), OpenAPIBackend reads docs/api/openapi.yaml. For GET /api/v1/packs/diabe-teach, it:

  1. Matches the path template /api/v1/packs/{packId} and identifies operationId: getCurriculumPackById.
  2. Runs securityHandlers.ApiKeyAuth, which calls verifyApiKeyHeader(request.headers.get("x-api-key"), deps) using timing-safe comparison. If invalid, unauthorizedHandler immediately returns 401 UNAUTHORIZED_TOKEN.
  3. Extracts c.request.params.packId ("diabe-teach") and passes it in context.params to getPackByIdHandler.
Step 3 · Inbound Request Transformer & Handler Factory src/adapters/inbound/http/get-pack-by-id.handler.ts + endpoint-handler.factory.ts

createGetPackByIdHandler(deps) uses our 3-step factory createEndpointHandler({ transformRequest, execute }): 

// 1. Pure Request Transformer: HTTP Request + RouteContext ──► Typed Query
export function transformGetPackByIdRequest({
  request,
  context,
}: HttpRequestInput): GetCurriculumPackByIdQuery {
  return {
    packId: resolvePackIdFromContext(context),
    bearerToken: parseBearerTokenHeader(request.headers.get("authorization")),
  };
}

Notice there is zero URL regex here—openapi-backend already extracted context.params.packId!

Step 4 · Application Use Case src/application/use-cases/get-curriculum-pack-by-id.use-case.ts

GetCurriculumPackByIdUseCase.execute(query) is 100% transport-agnostic (it knows nothing about HTTP headers, x-api-key, or Netlify):

  1. If query.bearerToken is present, it asks CapabilityTokenPort.verifyToken whether the caller is an "instructor" or "participant" (throwing UnauthorizedTokenError if tampered).
  2. Validates the slug via PackId.create(query.packId) (throwing PackNotFoundError on invalid slugs).
  3. Calls this.#packRepo.findById(packId) on CurriculumPackRepositoryPort.
Step 5 · Outbound Repository & Pure Domain Aggregate src/adapters/outbound/mongo-curriculum-pack-repository.ts + src/domain/curriculum-pack/curriculum-pack.ts

MongoCurriculumPackRepository.findById(packId) checks its in-memory built-in map first:

  • Fast path ("diabe-teach"): Returns the frozen 49-card DIABE_TEACH_PACK Aggregate Root in O(1) with zero MongoDB network queries.
  • Custom pack path (e.g., "cardio-teach"): Queries MongoDB's curriculum_packs collection via the warm-cached getMongoDatabase client and rehydrates CurriculumPack.create(doc).
Step 6 · Role-Aware DTO Projection & JSON Response src/application/dtos/curriculum-pack-projector.ts → endpoint-handler.factory.ts

Because the Diabe-Teach RCT uses the exact same 10 multiple-choice questions for both the Pretest and Posttest, CurriculumPackProjector.toPublicDto(pack, { includeAnswerKeys: callerRole === "instructor" }) projects a new DTO that omits correctIndex and explanation for anonymous/participant callers without mutating the immutable CurriculumPack Aggregate Root. Finally, createEndpointHandler serializes the result as a 200 OK JSON Response (or catches any DomainError and maps it via mapDomainErrorToResponse).
