# Hexagonal DDD Architecture, MongoDB Persistence, and Netlify Serverless API Deployment

We structure the backend and API using **Domain-Driven Design (DDD)** inside a strict **Hexagonal Architecture (Ports & Adapters)**, deployed on **Netlify Functions v2** (running on AWS Lambda) using **per-endpoint native `URLPattern` routing** (`netlify/functions/<endpoint>.ts` with `export const config: Config = { path, method }` and `context.params`) and backed by **MongoDB** (`curriculum_packs` and `game_sessions` collections with a warm-cached serverless `MongoClient` and document `version` optimistic concurrency control) in production. The inner **Domain Ring** models `GameSession` and `CurriculumPack` as transactional Aggregate Roots alongside pure, zero-I/O Domain Services (`BoardTopologyService`, `CurriculumPackValidatorService`, `RoundScoringService`, `MetacognitiveAnalyticsService`), while the **Application Ring** orchestrates use cases exclusively through inbound Driving Ports and outbound Driven Ports (`SessionRepositoryPort`, `CurriculumPackRepositoryPort`, `CapabilityTokenPort`, `NarrativeAdjudicatorPort`, `SessionEventPublisherPort`, `ClockPort`, `IdGeneratorPort`). Per-endpoint HTTP Driving Adapters accept `(request: Request, context?: { params?: Record<string, string | undefined> }) => Promise<Response>`, enabling native Netlify `context.params`, AWS Lambda `pathParameters`, and millisecond in-process contract testing without custom regex routing.
