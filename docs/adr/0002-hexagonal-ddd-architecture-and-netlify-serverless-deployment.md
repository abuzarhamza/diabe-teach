# Hexagonal DDD Architecture, MongoDB Persistence, and Netlify Serverless API Deployment

We structure the backend and API using **Domain-Driven Design (DDD)** inside a strict **Hexagonal Architecture (Ports & Adapters)** (`src/domain/`, `src/application/`, `src/adapters/inbound/`, `src/adapters/outbound/`), deployed on **Netlify Functions v2** (running on AWS Lambda) using **per-endpoint native `URLPattern` routing** (`netlify/functions/<endpoint>.ts` wired through shared `netlify/config/` runtime adapters `createNetlifyFunctionHandler` and `defineNetlifyRouteConfig`) and backed by **MongoDB** (`curriculum_packs` and `game_sessions` collections with a warm-cached serverless `MongoClient` and document `version` optimistic concurrency control) in production. The inner **Domain Ring** models `GameSession` and `CurriculumPack` as transactional Aggregate Roots alongside pure, zero-I/O Domain Services (`BoardTopologyService`, `CurriculumPackValidatorService`, `RoundScoringService`, `MetacognitiveAnalyticsService`), while the **Application Ring** orchestrates use cases exclusively through Inbound Ports (`*.port.ts`) and Outbound Ports (`SessionRepositoryPort`, `CurriculumPackRepositoryPort`, `CapabilityTokenPort`, `NarrativeAdjudicatorPort`, `SessionEventPublisherPort`, `ClockPort`, `IdGeneratorPort`), with all interface/type/DTO contracts (`*.types.ts`, `*.port.ts`, `*.dto.ts`) strictly separated from class and factory implementations across every ring. Each HTTP Inbound Adapter (`src/adapters/inbound/http/`) follows a composable **Request Transformer + Endpoint Handler Factory** pipeline (`createEndpointHandler({ transformRequest, execute })`) accepting `(request: Request, context?: RouteContext) => Promise<Response>`, enabling native Netlify `context.params`, AWS Lambda `pathParameters`, and millisecond in-process contract testing without custom regex routing or duplicated error-handling boilerplate.
