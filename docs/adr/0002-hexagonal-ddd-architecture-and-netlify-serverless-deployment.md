# Hexagonal DDD Architecture, MongoDB Persistence, and Netlify Serverless API Deployment

We structure the backend and API using **Domain-Driven Design (DDD)** inside a strict **Hexagonal Architecture (Ports & Adapters)**, deployed on **Netlify Functions v2** behind a single catch-all Web-Standard `Request`/`Response` driving adapter (`/api/v1/*`) and backed by **MongoDB** (`curriculum_packs` and `game_sessions` collections with a warm-cached serverless `MongoClient` and document `version` optimistic concurrency control) in production. The inner **Domain Ring** models `GameSession` and `CurriculumPack` as transactional Aggregate Roots alongside pure, zero-I/O Domain Services (`BoardTopologyService`, `CurriculumPackValidatorService`, `RoundScoringService`, `MetacognitiveAnalyticsService`), while the **Application Ring** orchestrates use cases exclusively through inbound Driving Ports and outbound Driven Ports (`SessionRepositoryPort`, `CurriculumPackRepositoryPort`, `CapabilityTokenPort`, `NarrativeAdjudicatorPort`, `SessionEventPublisherPort`, `ClockPort`, `IdGeneratorPort`). This keeps all pedagogical, topological, and metacognitive rules completely isolated from HTTP transport, MongoDB BSON drivers, LLM SDKs, and serverless cold-start/stateless constraints, enabling millisecond in-process contract testing via `app.fetch(request)` with deterministic in-memory driven adapters while deploying cleanly to Netlify Functions v2 + MongoDB.
