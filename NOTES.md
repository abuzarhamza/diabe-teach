# Teaching Notes & Learner Preferences

- **Terminology preference**: Always use **`inbound`** (`src/adapters/inbound/`) and **`outbound`** (`src/adapters/outbound/`) instead of `driving` and `driven`.
- **100% Class-Based Object-Oriented Modules & No God Modules**: Every implementation file in `src/` must be a cohesive `class` (`AppRuntime`, `OpenApiHttpApp`, `BaseHttpHandler`, `GetPackByIdHttpHandler`, `GetCurriculumPackByIdUseCase`, `CurriculumPackProjector`, `MongoCurriculumPackRepository`, `MongoConnectionManager`, `CurriculumPack`, `PackId`) with zero loose procedural helper/factory functions, and every interface/contract (`*.types.ts`, `*.port.ts`, `*.dto.ts`) must live in its own separate file.
- **Top-Level Visibility for Runtime Wiring**: Keep runtime environment and dependency wiring visible at the root of `src/` (`src/app-runtime.ts` + `src/app-runtime.types.ts`) rather than hidden inside `src/config/` or `netlify/config/`, and keep all MongoDB collection/connection wiring inside `src/adapters/outbound/`.
- **Routing preference**: Use established libraries (`openapi-backend` reading `docs/api/openapi.yaml` inside `OpenApiHttpApp`) with **one single entrypoint** (`netlify/functions/api.ts`) rather than custom routers or scattered per-endpoint Netlify function files.
- **Visual learning style**: Prefers clear, step-by-step end-to-end execution traces showing how a request flows from Netlify into each class and back out as an HTTP response.
