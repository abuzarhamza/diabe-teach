# Spec: `GET /api/v1/packs/{packId}` — Hexagonal DDD Vertical Slice with `openapi-backend` YAML Routing, Netlify Deployment Config & MongoDB

Status: ready-for-agent

## Problem Statement

Every workflow in the Concept-Chain Educational Game Platform—rendering the 7×7 keyword board, running the 15-minute Trial Orientation with Figure 2 Calibration Examples, administering the 10-question Pretest/Posttest Assessment Instrument, and collecting the 9-item Perception Survey—depends on fetching a **Curriculum Pack** by its `packId` via `GET /api/v1/packs/{packId}`.

Serving `GET /api/v1/packs/{packId}` on **Netlify Functions v2** (and **AWS Lambda** under the hood) while keeping the codebase easy to read, review, and scale across all 14 endpoints requires satisfying seven constraints simultaneously:
1. **Complete Clinical Fidelity**: The built-in `diabe-teach` Curriculum Pack must accurately expose all 49 verbatim Appendix 1 Keyword Cards, 7 Semantic Domains, the Figure 2 reference 7×7 board and Calibration Examples (Valid Chain A [9 cards], Valid Chain B [7 cards], and Invalid Chain C [non-adjacent transition]), 10 Bloom Level 2/3 multiple-choice questions, and 9 Appendix 2 Likert survey items.
2. **Answer-Key Secrecy Across Pretest and Posttest**: Anonymous callers and learners holding a `participantToken` must never receive `correctIndex` or `explanation` in `GET /api/v1/packs/{packId}`, whereas an instructor holding a valid `instructorToken` must receive the full unredacted assessment key—and a caller passing a malformed or tampered `Authorization` header must receive an immediate `401 UNAUTHORIZED_TOKEN` error.
3. **Hexagonal DDD Ring Isolation (`domain`, `application`, `adapters/inbound`, `adapters/outbound`)**: The `CurriculumPack` Aggregate Root and `PackId` Value Object in the Domain Ring must remain 100% pure and free of HTTP, OpenAPI, Netlify, or MongoDB driver concerns.
4. **No God Modules & 100% Class-Based Object-Oriented Modules (Strict Separation of Interface/Contract Files from Class Files)**: Every module across all rings must separate TypeScript interfaces, ports, DTOs, and configuration contracts (`*.types.ts`, `*.port.ts`, `*.dto.ts`) from cohesive `class` implementations (`*.ts`, `*.use-case.ts`, `*.handler.ts`), avoiding loose procedural helper/factory functions.
5. **Template-Method Class Hierarchy for Inbound HTTP Handlers (`BaseHttpHandler` & `GetPackByIdHttpHandler`)**: Inbound HTTP handlers must be structured as classes extending an abstract `BaseHttpHandler<TQuery, TResult>` class (`handle(request, context)` calling `transformRequest -> execute -> BaseHttpHandler.jsonResponse / BaseHttpHandler.mapDomainErrorToResponse`), eliminating free procedural functions.
6. **Central YAML Routing via Class-Based `OpenApiHttpApp` (`openapi-backend` + `docs/api/openapi.yaml`)**: Instead of scattering routes across many files or returning anonymous closures, all API routing must be encapsulated in an `OpenApiHttpApp` class reading `docs/api/openapi.yaml` and dispatching matched `operationId`s (such as `getCurriculumPackById`) to their endpoint handler classes.
7. **Visible Top-Level `AppRuntime` Class in `src/` & Encapsulated Outbound Mongoose Classes**: All MongoDB/Mongoose connection pooling (`MongoConnectionManager`), Mongoose `Schema` / `Model` definition (`curriculumPackSchema`, `MongoCurriculumPackRepository.getModel`), and collection wiring (`MongoCurriculumPackRepository` using `.lean()`) must be classes inside `src/adapters/outbound/`, runtime environment and dependency assembly must be a visible top-level `AppRuntime` class in `src/app-runtime.ts` (with contracts in `src/app-runtime.types.ts`), and `netlify/functions/api.ts` must be the sole file under `netlify/`.

## Solution

Implement the end-to-end **`GET /api/v1/packs/{packId}`** vertical slice using **100% cohesive classes** across all four Hexagonal DDD rings (`Domain`, `Application`, `Inbound Adapters`, `Outbound Adapters` with **MongoDB**) plus the top-level `AppRuntime` class (`src/app-runtime.ts`), centrally routed by **`openapi-backend`** (`OpenApiHttpApp`) from `docs/api/openapi.yaml` and deployed via the single **Netlify Functions v2** entrypoint (`netlify/functions/api.ts` + `netlify.toml`):

1. **Domain Ring (`src/domain/`)**:
   - Separate all Value Object and Aggregate property contracts (`AdjacencyRule`, `BoardConfig`, `SemanticDomain`, `KeywordCard`, `GridCoord`, `CalibrationExample`, `AdjudicationRubric`, `AssessmentQuestion`, `AssessmentInstrument`, `PerceptionSurveyItem`, `PerceptionSurvey`, `CurriculumPackProps`) into `curriculum-pack.types.ts`.
   - Implement the `PackId` Value Object class (`pack-id.ts`), the immutable `CurriculumPack` Aggregate Root class (`curriculum-pack.ts`, with private static `#normalizeLookupKey` and `#deepFreeze` methods so zero loose functions exist), the canonical built-in `DIABE_TEACH_PACK` (`diabe-teach-pack.ts`), and typed `DomainError` classes (`PackNotFoundError`, `UnauthorizedTokenError` in `domain-errors.ts`).
2. **Application Ring (`src/application/`)**:
   - Separate Inbound Port contracts (`GetCurriculumPackByIdQuery`, `GetCurriculumPackByIdResult`, `GetCurriculumPackByIdDependencies`, `GetCurriculumPackByIdUseCasePort` in `get-curriculum-pack-by-id.port.ts`), Outbound Port contracts (`CurriculumPackRepositoryPort`, `CapabilityTokenPort`), and DTO contracts (`PublicAssessmentQuestionDto`, `PublicCurriculumPackDto`, `CurriculumPackProjectionOptions` in `curriculum-pack.dto.ts`).
   - Implement the `GetCurriculumPackByIdUseCase` class (`get-curriculum-pack-by-id.use-case.ts`) and `CurriculumPackProjector` class (`curriculum-pack-projector.ts`).
3. **Inbound HTTP Adapter Ring (`src/adapters/inbound/http/`)**:
   - Separate HTTP handler contracts (`RouteContext`, `HttpRequestInput`, `EndpointHttpHandler`, `ApiKeyValidationConfig`, `GetPackByIdHandlerDependencies`, `AppDependencies`, `HttpApp`) into `http-handler.types.ts`.
   - Implement the abstract `BaseHttpHandler<TQuery, TResult>` class (`base-http.handler.ts`) providing `handle(request, context)`, `BaseHttpHandler.verifyApiKeyHeader`, `BaseHttpHandler.parseBearerTokenHeader`, `BaseHttpHandler.jsonResponse`, and `BaseHttpHandler.mapDomainErrorToResponse`.
   - Implement the `GetPackByIdHttpHandler` class (`get-pack-by-id.handler.ts`) extending `BaseHttpHandler`, and the `OpenApiHttpApp` class (`open-api-http-app.ts` / `create-app.ts`) wrapping `OpenAPIBackend` (`docs/api/openapi.yaml`).
4. **Outbound Adapters Ring (`src/adapters/outbound/`), Top-Level `AppRuntime` Class (`src/app-runtime.ts`), & Single Netlify Entrypoint (`netlify/functions/api.ts`)**:
   - Separate MongoDB/Mongoose repository contracts (`CurriculumPackDocument`, `CurriculumPackCollectionLike`, `MongoCurriculumPackRepositoryOptions`, `MongoCurriculumPackConnectionConfig`) into `mongo-curriculum-pack-repository.types.ts`.
   - Extract Mongoose schema definition into `curriculum-pack.schema.ts` (`curriculumPackSchema`) and simplify `MongoCurriculumPackRepository` with flat query execution and a private static `#toDomain(doc)` helper to minimize cognitive complexity.
   - Implement the `MongoConnectionManager` class (`mongo-client-singleton.ts` managing warm-cached `mongoose.Connection` pools), alongside `InMemoryCurriculumPackRepository`, `HmacCapabilityTokenAdapter`, and `FakeCapabilityTokenAdapter`.
   - Implement the top-level `AppRuntime` class (`src/app-runtime.ts` + `src/app-runtime.types.ts`) so runtime configuration is immediately visible at the root of `src/` rather than hidden in `src/config/runtime.config.ts`, and wire it into `netlify/functions/api.ts`.

## User Stories

1. As a learner or anonymous client calling `GET /api/v1/packs/diabe-teach` with no `Authorization` header, I want to receive `200 OK` with `{ pack: PublicCurriculumPack }` containing all 49 Appendix 1 Keyword Cards, 7 Semantic Domains, `boardConfig` (`7×7`, `minChainLength: 4`, `"chebyshev-8"`), Figure 2 Calibration Examples (Chains A, B, and C), 10 assessment questions, and 9 perception survey items.
2. As a study administrator, when an anonymous caller requests `GET /api/v1/packs/diabe-teach`, I want `correctIndex` and `explanation` omitted from every question in `pack.assessmentInstrument.questions`, so that learners cannot inspect network responses to find Pretest/Posttest answers.
3. As a learner calling `GET /api/v1/packs/diabe-teach` with a valid `Authorization: Bearer <participantToken>`, I want to receive `200 OK` with `correctIndex` and `explanation` omitted from `pack.assessmentInstrument.questions`, matching the redacted learner view.
4. As an instructor calling `GET /api/v1/packs/diabe-teach` with a valid `Authorization: Bearer <instructorToken>`, I want to receive `200 OK` with `correctIndex` (`0..3`) and `explanation` included on every question in `pack.assessmentInstrument.questions`, so that I can review the complete answer key.
5. As an API consumer passing a malformed `Authorization` header (e.g., non-Bearer scheme, empty token, or invalid/tampered token signature) to `GET /api/v1/packs/{packId}`, I want to receive `401 Unauthorized` with `{ code: "UNAUTHORIZED_TOKEN", message: "..." }`, so that broken authentication headers are surfaced immediately instead of silently returning a redacted response.
6. As an API consumer requesting an unknown `packId` (e.g., `GET /api/v1/packs/unknown-pack`) that is neither built-in nor present in the MongoDB `curriculum_packs` collection, I want to receive `404 Not Found` with `{ code: "PACK_NOT_FOUND", message: "Curriculum Pack 'unknown-pack' was not found.", details: { packId: "unknown-pack" } }`.
7. As a learner inspecting the `diabe-teach` pack's Keyword Cards, I want each of the 49 cards to include `id`, `verbatimLabel` (exact string from Appendix 1, such as `"Hyperglycaemia"` and `"Lipo-hypertrophy"`), `displayLabel`, `aliases` (such as `["Hyperglycemia"]` and `["Lipohypertrophy", "lipodistrophy"]`), `domainId`, and `summary`.
8. As a learner in the 15-minute Trial Orientation phase, I want `pack.adjudicationRubric` on `diabe-teach` to include the 7×7 `calibrationBoardCardIds` matrix from Figure 2 of the publication alongside the three `calibrationExamples` (Valid Chain A with 9 cards, Valid Chain B with 7 cards, and Invalid Chain C with 4 cards and `isValid: false` due to non-adjacent `Islet Cells` and `Pancreas`).
9. As a game creator who has stored a custom `CurriculumPack` document (e.g., `_id: "cardio-teach"`) in the MongoDB `curriculum_packs` collection, I want `GET /api/v1/packs/cardio-teach` to load the document from MongoDB, rehydrate the `CurriculumPack` Aggregate Root, and apply the exact same role-aware answer-key projection as the built-in `diabe-teach` pack.
10. As a player requesting `GET /api/v1/packs/diabe-teach` on Netlify Functions v2, I want `MongoCurriculumPackRepository` to serve the built-in `diabe-teach` pack directly from in-memory constants in $O(1)$ without making a MongoDB network query.
11. As a backend developer, I want all API routes and `operationId` mappings defined in one central YAML file (`docs/api/openapi.yaml`) and dispatched by the official `openapi-backend` framework in `createApp(deps)`, so that I never have to maintain custom regex routers or duplicate route definitions across files.
12. As an API consumer calling an unknown URL or an OpenAPI operation that has not been registered yet, I want `openapi-backend`'s `notFound` and `notImplemented` handlers in `createApp(deps)` to return a structured JSON `ApiErrorResponse` (`404` / `501`) rather than an unhandled exception.
13. As a platform engineer deploying to Netlify Functions v2, I want all MongoDB connection/collection wiring inside classes in `src/adapters/outbound/`, runtime dependency configuration in a visible top-level `AppRuntime` class (`src/app-runtime.ts`), and only `netlify/functions/api.ts` inside `netlify/`, so that nothing is hidden in subfolders or written as loose functions.
14. As a code reviewer, I want every implementation module in the codebase to be a cohesive `class` (with zero loose procedural helper/factory functions) and every contract/interface definition to live in a dedicated `*.types.ts`, `*.port.ts`, or `*.dto.ts` file.
15. As a developer running `lint:boundaries`, I want `dependency-cruiser` to verify that Domain and Application modules never import `mongodb`, `openapi-backend`, or `@netlify/functions`, that Inbound and Outbound Adapters never import each other directly, and that `mongodb` is strictly isolated to `src/adapters/outbound/`.
16. As a platform operator protecting `/api/v1/*` routes with a client API key, when `apiKey` (or `requireApiKey: true` in Netlify production via `process.env.API_KEY`) is configured, I want requests with a missing or mismatched `x-api-key` header (or when `API_KEY` is unset in production) to be rejected at the `openapi-backend` `ApiKeyAuth` security handler with `401 Unauthorized` (`{ code: "UNAUTHORIZED_TOKEN", message: "Missing or invalid x-api-key header." }`), while valid `x-api-key` requests proceed to `Authorization: Bearer` session role evaluation without leaking `x-api-key` concerns into the Domain, Application, or individual endpoint handler modules.
17. As a maintainer, I want a single Netlify Function entrypoint (`netlify/functions/api.ts`) and a single class-based route dispatcher (`OpenApiHttpApp` reading `docs/api/openapi.yaml`), with no redundant per-endpoint Netlify function files (`get-pack-by-id.ts`), no hidden `src/config/` or `netlify/config/` folder, and no loose procedural functions.

## Implementation Decisions

- **Class-Based Central YAML Routing & `ApiKeyAuth` Security (`OpenApiHttpApp` in `src/adapters/inbound/http/create-app.ts`)**:
  - `OpenApiHttpApp` (`implements HttpApp`) encapsulates `OpenAPIBackend` pointed at `docs/api/openapi.yaml` with `quick: true` and `validate: false`.
  - Registers the `ApiKeyAuth` security handler (`securityHandlers.ApiKeyAuth`) and `unauthorizedHandler` using `BaseHttpHandler.verifyApiKeyHeader` against `deps.apiKey` / `deps.requireApiKey`, returning `401 Unauthorized` (`{ code: "UNAUTHORIZED_TOKEN", message: "Missing or invalid x-api-key header." }`) on failure.
  - Maps `operationId: getCurriculumPackById` to `new GetPackByIdHttpHandler(deps).handle(request, context)`.
  - Registers `notFound` and `notImplemented` handlers returning structured JSON `Response` objects via `BaseHttpHandler.jsonResponse`.
- **Class-Based Template-Method Pipeline for Inbound HTTP Handlers (`src/adapters/inbound/http/`)**:
  - `BaseHttpHandler<TQuery, TResult>` in `endpoint-handler.factory.ts` is an abstract class providing `public async handle(request, context): Promise<Response>` (`transformRequest -> execute -> BaseHttpHandler.jsonResponse / BaseHttpHandler.mapDomainErrorToResponse`), plus static utility methods (`verifyApiKeyHeader`, `parseBearerTokenHeader`, `jsonResponse`, `mapDomainErrorToResponse`).
  - `GetPackByIdHttpHandler` in `get-pack-by-id.handler.ts` extends `BaseHttpHandler<GetCurriculumPackByIdQuery, GetCurriculumPackByIdResult>`, implementing `public transformRequest(input)` and `protected execute(query)`.
- **No God Modules & 100% Class-Based Modules Across All Rings**:
  - Domain contracts in `curriculum-pack.types.ts` (and `CurriculumPack` encapsulates `#normalizeLookupKey` and `#deepFreeze` as private static methods); Application contracts in `get-curriculum-pack-by-id.port.ts`, `curriculum-pack-repository.port.ts`, `capability-token.port.ts`, and `curriculum-pack.dto.ts`; Inbound HTTP contracts in `http-handler.types.ts`; Outbound MongoDB contracts in `mongo-curriculum-pack-repository.types.ts` (with `MongoConnectionManager` class in `mongo-client-singleton.ts`); Top-level runtime contracts in `src/app-runtime.types.ts`.
- **Visible Top-Level `AppRuntime` Class (`src/app-runtime.ts`) & Single Netlify Entrypoint (`netlify/functions/api.ts`)**:
  - `AppRuntime` in `src/app-runtime.ts` (with types in `src/app-runtime.types.ts`) sits directly at the root of `src/` so it is never hidden inside a subfolder, providing `AppRuntime.loadEnvConfig`, `AppRuntime.buildProductionDependencies`, `AppRuntime.getProductionDependencies`, `AppRuntime.createServerlessHttpHandler`, and `AppRuntime.defineServerlessRouteConfig`.
  - `AppRuntime.buildProductionDependencies` passes the parsed `config` object directly to `MongoCurriculumPackRepository.fromConfig(config)` (with no nested arrow-function callback or duplicate `loadEnvConfig` call) and uses `HmacCapabilityTokenAdapter.fromSecret(config.capabilityTokenSecret)` so dependency construction is a flat, 4-property object literal.
  - `AppRuntime.createServerlessHttpHandler(customDeps?)` resolves `const deps = customDeps ?? AppRuntime.getProductionDependencies()` inside the method body for clear readability.
  - `netlify/functions/api.ts` is the sole file under `netlify/`, delegating to `AppRuntime.createServerlessHttpHandler()` and `AppRuntime.defineServerlessRouteConfig(...)`.

## Testing Decisions

- **Primary Testing Seam (`OpenApiHttpApp`, `GetPackByIdHttpHandler`, `AppRuntime`, & `netlify/functions/api.ts`)**:
  - Exercise `new OpenApiHttpApp(deps).fetch(request)` through `openapi-backend` (`docs/api/openapi.yaml` $\to$ `operationId: getCurriculumPackById` $\to$ `GetPackByIdHttpHandler.transformRequest` $\to$ `GetCurriculumPackByIdUseCase.execute` $\to$ `CurriculumPackProjector.toPublicDto`).
  - Exercise `new GetPackByIdHttpHandler(deps).handle(request, { params: { packId: "diabe-teach" } })` and `transformRequest` directly.
  - Exercise `netlify/functions/api.ts` and `AppRuntime` (`AppRuntime.loadEnvConfig`, `AppRuntime.createServerlessHttpHandler`, `AppRuntime.defineServerlessRouteConfig`).
  - Verify `404` / `501` responses when calling unknown routes or unimplemented OpenAPI operations in `docs/api/openapi.yaml`.
